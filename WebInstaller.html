Storage and recovery details
SHARED BEETLE / BEETLE BLUE STORAGE POLICY: BEETLE uses 12 A/B-journalled project slots in 0x97000–0xDFFFF. This experimental storage variant can erase existing ETCH/Felucca user data during first-use initialization or an explicit WIPE ALL. The existing project transfer and backward-compatible native project decoder are retained; V23 project-owned short samples remain separate from the PC-only global sample library. This installer does not back up flash. Once the vendor loader takes over, it controls firmware writing. Back up all data before installing, because a failed firmware update may require independent hardware recovery.

Technical installation notes

READ-ONLY DEVICE CHECK only sends identity queries; it does not start any update or write to flash. The identification FM-1_900 is shared; a successful handshake alone does not prove loader compatibility. A reboot between CHECK and FLASH is expected. If it reconnects to the old version instead of the OTA loader, the log records it. Save the log if an update fails.

A successful USB transfer is not enough. This installer only verifies the returned firmware product identity after restart; that identity is shared with V1.4.1 and is NOT a cryptographic proof that the new application started. Verify the firmware version and audio behavior on the device.

FIRMWARE HUB DIAGNOSTICS: If the Hub says "Different firmware's update loader is running", use the read-only Hub checker first. A working BEETLE application and an actual update loader need to be distinguished. BEETLE now recognizes CRC-verified Felucca-family application-only loaders beyond its former SHA pin, but firmware switching via The Firmware Hub is NOT hardware verified. Official V15 remains exact-image-pinned; unknown loader families remain blocked.
