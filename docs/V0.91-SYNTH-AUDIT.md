# BEETLE BLUE V0.91: inherited BEETLE synth audit

The source was examined for remaining synthesizer-specific code. Code inventory and recommendation, not a performance benchmark:

| Source / path | Finding | V0.91 decision |
|---|---|---|
| `track_runtime.h` audio renderer | `track_chip_render` calls are compiled only for non-drum builds, guarded by `!BEETLE_DRUM_EDITION`. The six BLUE drum-lane audio path does not render synth voices. | Keep the audio guards. No additional DSP CPU usage for those synth render calls in BLUE. |
| `track_runtime.h` old `track_page == 5` editor, wavetable/type chooser and synth live-input functions | BEETLE synthesizer UI and note plumbing remain in source. BLUE hardware EDIT opens Drum Editor (page 16) instead. | Candidate for refactoring in a future measured build; do not delete whole shared handlers blindly. |
| `track_chip.c`, `track_chip.h` and patch structures | Synth-engine implementation and instrument initialization remain compiled into the source tree. | Potential ROM/data reductions, but require real linker map A/B measurement, code paths and host tests. |
| `track_project_store.c/.h` instrument and type-preset fields | The current BDR1 V30 serialized project still contains older BEETLE instrument fields for compatibility, migration, offsets and checksums. | Retain these until a new versioned codec is written and independently tested. Removing fields now would break V29/V30 save/load. |
| `beetle_instrument_library.h` and patches | Synth-library structures are retained in project bytes. | Do not blindly remove; migrate separately with complete compatible serializer and rollback fixtures. |
| `track_master_fx` and Punch-In effects | Used by drum performance and mixing. | Keep. |
| `beetle_storage_v2*`, sample streaming, USB audio, OTA, LCD and HAL | Needed for drum kit bank, projects, samples and device interaction. | Keep. |
| third-party licence and original source credits | Attribution needs preservation despite excluding on-device reSID label. | Keep legally required source-level notices. |

**CPU caveat.** Removing code that is not executing does not automatically free realtime CPU. A performance claim requires measured worst-case DMA/audio timing on an actual FM1. Previous reported double-kick `DMA DEADLINE` is not yet conclusively solved by the current software-only stress checks.

**Storage caveat.** This release intentionally retains 48 patterns and 12 project slots. Increasing to 64/16 requires a verified new NOR partition allocation and project-bank limit audit, not replacing constants.

**Webtools safety.** Volume migration/marker repair have been disabled in the BLUE Project Manager because global BBK1 preset-bank backups are not yet supported. Individual project import/export and global U01-U13 samples remain available as supported by the native protocol. USB behavior is not physically validated.
