# BEETLE BLUE V1.4 — OTA staging and flash compatibility

## Diagnosis

The V1.3.1 OTA stage-1 application checks ownership of the 20 KiB staging window at `0xE0000..0xE4FFF`. Its loader core clears the final 4 KiB commit sector after a successful installation, including the ownership token at `0xE4F80`, but leaves the staged loader body intact. The application recognizes only the exact older 6,898-byte loader body. V1.3.1 ships a 7,280-byte body, so it can refuse its own legitimate post-installation staging state with `-15`, independent of the destination firmware and chip type. This condition was reproduced by compiling the original V1.3.1 `ota.c` and replaying the exact release loader bytes. It is a concrete defect; the user's physical flash contents have not been dumped here.

A second defect was repeated evaluation of the hardware-reading expression inside `FL_JEDEC_OK`, plus identification at every erase/page program. Both app and RAM loader now use a single-evaluation predicate, three bounded attempts on an unrecognized result, and a success-only cache for the current power session. OTA also explicitly checks JEDEC before erasing staging. Unknown IDs remain refused. This does not establish electrical compatibility with arbitrary future hardware.

V1.4 recognizes the exact V1.3, V1.3.1 and V1.4 staged loader bodies by length and SHA-256, retaining the existing ownership and unknown-content policy. The release builder checks the exact current loader digest is in the app; the WebInstaller pins all three. The V15 stock path retains its existing flash-image pin and loader metadata check, and now checks the complete loader body CRC before erase. The 15-minute OTA budget, transfer preemption, app-only writer bounds, boot header, identity and project storage are unchanged.

## Hardware and recovery references

- The Firmware Hub submission guidance, https://thefirmwarehub.com/submit/ (two 1 MiB NOR IDs).
- Felucca issue #320 and 1.8.2 release, https://github.com/hugelton/Felucca/issues/320 and https://github.com/hugelton/Felucca/releases/tag/v1.8.2 (UC25HQ80 support tested by upstream contributor mistakenideas, not a BLUE hardware test).
- The Firmware Hub rescue, https://thefirmwarehub.com/tools/rescue/ (independent ROM/download route).
- FM-1 developers' recovery wiki, https://sbegueria.github.io/fm1-dev-wiki/Recovery.html (official V15 exact hash and differing V16).
- Quixotic7 unbricker, https://github.com/Quixotic7/MvaveFM1Unbricker (different V15/V16 image and bootloader regions).

If V1.3.1 is already refusing all targets, a fixed target package cannot repair the running stage-1 code. Back up the full flash and use a verified independent recovery method. Do not wipe BEETLE storage to solve an OTA staging problem. This release is not a guarantee of universal OTA across unknown loaders, chip IDs, bootloader layouts, power loss or physical flash faults.
