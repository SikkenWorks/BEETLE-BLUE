# BEETLE BLUE V0.99.7 validation (software only)

## Implemented

- Setlist dirty-state is committed automatically on **HOME** or **SEL** exit; success is intentionally invisible.
- Failed CRC-checked Storage V2 A/B footer write retains in-memory edits, shows retry and prevents leaving Setlist.
- Live Mode checks `active`, `ready`, `error`, `finished`, native safety/trip flags and pending completion before starting a project. Native audio ISR does not load flash projects.
- Uncalibrated four-stage FM1 battery ADC HUD and USB data-link bolt (not charger detection) are shown in reserved tracker/Perform rectangles.

## Verified by software

- Native JieLi Storage V2/updater/USB/BLUE build (verify `native-build-options.json`).
- Native read-only hardware-test variant builds with forbidden flash-writer symbols absent.
- Firmware app entry/audit, original protected flash header and OTA loader unchanged, `.fwsc` roundtrip SHA verified.
- A/B setlist commit, multiple writes, simulated interrupted write, project-slot isolation.
- Autosave unit tests: no dirty write, success, failed write, retry, missing writer.
- Battery policy threshold and invalid ADC handling tests.
- BLUE sample engine baseline: cross-kit hi-hats, U01–U13 self-choke, repeat prewarming and PCM-equivalence.
- Native-source extracted 240×240 Live Mode captures with pixel-perfect 8× scaling, manual geometry audit for two new HUD placements; not a complete visual audit of every BEETLE screen.
- WebInstaller embeds byte-for-byte identical `.fwsc` and Manager embeds identical WebInstaller and Project Manager.

## Explicitly NOT proven

- Physical FM1 lithium battery percentage mapping, charger/charge-complete detection, VBUS status. Bolt = enumerated USB only.
- End-to-end FM1 project loading latency, stage stability, power-loss behaviour during flash commit and absolute immunity to PCM/DMA failures.
- Physical peak loudness, all-six-channel audio+USB recording stresses, and physical LCD placement.
- Real FM1 OTA firmware recovery. Do not claim this version stage-safe.

**Do not use as a critical stage device until physical tests with a verified independent recovery method and full backup are completed.**
